# Cómo volver a poner el dominio

Este repositorio tiene el fichero del dominio **desactivado a propósito**, renombrado a
`CNAME.pendiente`.

## Por qué

GitHub Pages solo sirve una dirección. Con el fichero `CNAME` puesto, la dirección
`blasmani.github.io/PAGINA-WEB-CONNECTA-DIGITAL-SOLUTIONS/` **redirige** (301) a
`connectadigitalsolutions.com` — y ese dominio todavía apunta al aparcamiento de GoDaddy
(`3.33.130.190`, `15.197.148.33`), así que la web no se veía por ningún lado: ni en
`github.io` porque redirige, ni en el dominio porque el DNS no llega a GitHub.

Desactivándolo, el sitio se ve YA en la dirección de `github.io` y se puede revisar.

## Cuándo y cómo volver a activarlo

En cuanto el DNS de GoDaddy apunte a GitHub (los cuatro registros `A` y el `CNAME` de `www`
que están en el README):

```bash
git mv CNAME.pendiente CNAME
git commit -m "Volver a poner el dominio: el DNS ya apunta a GitHub"
git push
```

Y en `Settings → Pages`, marcar **Enforce HTTPS** cuando GitHub haya emitido el certificado
(tarda unos minutos desde que el DNS es correcto).

## Un detalle mientras esté desactivado

`404.html` usa rutas absolutas (`/assets/styles.css`) a propósito, porque GitHub Pages sirve
ese mismo fichero para cualquier ruta inexistente y con rutas relativas saldría sin estilos.
Mientras el sitio viva bajo `github.io/PAGINA-WEB-.../`, esas rutas absolutas apuntan a la
raíz de `github.io` y **la página de error se ve sin estilos**. En el dominio propio funciona
bien. No se toca: arreglarlo para el enlace provisional lo rompería en el definitivo.
